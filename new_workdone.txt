1. PROBLEM STATEMENT
================================================================================

Previous pipeline achieved ~40% accuracy with linear models on run-level features.
Goal: improve accuracy using better feature extraction and nonlinear mathematical models.

Constraints:
  - Mathematical models only (no ML: no trees, no ensembles, no neural nets)
  - LOSO cross-validation (leave-one-subject-out)
  - 4-class difficulty prediction (levels 1-4)
  - Physiological signals only (no aircraft state features — ground truth contamination)

================================================================================
2. WHAT WAS WRONG WITH PREVIOUS PIPELINE
================================================================================

1. Single summary per ~5min run → collapses all temporal dynamics into 1 row
2. Too few features: ECG=10, EDA=5, EMG=3
3. Silent exception swallowing (except: pass everywhere)
4. Aircraft state, head tracking, oculomotor events never used
5. Linear model ceiling (logistic regression)
6. Only ~408 samples total

================================================================================

1. Windowing helped: 34.3% linear (new) vs ~40% linear (old on 408 samples)
   Note: old pipeline had ~40% on run-level, new has 34.3% on window-level.
   Window-level is harder because within-run windows share temporal context.

   Polynomial (32.6%) and KRR (30.5%) performed WORSE — likely overfitting.

3. Adjacent accuracy is high (71.5%): most errors are ±1 level misclassification.
   The model captures the ordinal structure but struggles with fine-grained discrimination.

4. Binary accuracy ~61%: modest improvement over 50% chance for low-vs-high split.

5. Level 2 is hardest to classify (26.5% correct): it gets confused with both L1 and L3.
   Levels 1 and 4 (extremes) are easiest (41.7% and 44.4%).

6. High inter-subject variability: some subjects reach 57% while others are at 14%.
   This suggests strong individual differences in physiological responses.

7. Aircraft state features (dropped) would have boosted accuracy significantly
   (ac_pitch_std had eta_sq=0.091, highest of all features) but they measure
   the experimental condition, not the pilot's physiological state.

8. FEATURE ENHANCEMENT (enhance_features.py)
================================================================================

Problem: Previous models peaked at 35.9% because raw features don't account for
inter-subject physiological variability. Subject A's HR=75 and Subject B's HR=75
may represent very different workload states.

Enhancement 1 — Subject Z-scoring (rest baseline mean + std):
  - Re-processed rest recordings with 30-sec windowing (same as task pipeline)
  - For each subject: computed rest feature MEAN and STD across rest windows
  - Z-scored task features: z = (task_value - rest_mean) / rest_std
  - This normalizes each subject relative to their OWN resting physiology
  - No leakage: rest baseline is pre-experiment data, not task data
  - 16 z-scored features added: z_ecg_hr_mean, z_eda_scr_count, z_emg_flexor_rms,
    z_emg_extensor_rms, z_emg_cocontraction, z_emg_acc_rms, + 10 more

Enhancement 2 — Window Position:
  - window_position = window_index / max_window_in_run (range 0.0 to 1.0)
  - Captures WHERE in the ILS approach this window falls
  - Early approach vs final descent have different workload demands
  - 1 feature added

Enhancement 3 — Temporal Delta (change from first window):
  - tdelta_X = X_current_window - X_first_window
  - Captures physiological BUILDUP during the approach
  - 8 features: tdelta_ecg_hr_mean, tdelta_eda_scl_mean, tdelta_emg_flexor_rms,
    tdelta_emg_extensor_rms, tdelta_eye_pupil_mean, tdelta_eye_blink_rate,
    tdelta_head_pitch_std, tdelta_ecg_rmssd (dropped, <50% coverage)

Enhancement 4 — Temporal Slope (per-run trend):
  - slope_X = linear fit slope of X across all windows in a run
  - Captures RATE of change (e.g., "HR increasing 2 bpm/window")
  - 8 features: slope_ecg_hr_mean, slope_ecg_rmssd, slope_eda_scl_mean,
    slope_emg_flexor_rms, slope_emg_extensor_rms, slope_eye_pupil_mean,
    slope_eye_blink_rate, slope_head_pitch_std

Result: 90 columns → 123 columns (117 features + 6 metadata)

11. DATA LEAKAGE AUDIT
================================================================================

Full pipeline audited for data leakage. One issue found and fixed:

ISSUE: Feature screening (ANOVA + VIF) was done on the FULL dataset including
test subjects BEFORE the LOSO loop. This means the test subject's data
influenced which features were selected.

FIX: Moved feature screening INSIDE each LOSO fold — screening now runs on
training data only. Each fold selects its own feature set independently.

Components verified clean:
  - new_data_pipeline.py: all feature extraction per-window, no cross-subject ✅
  - enhance_features.py z-scoring: uses subject's own rest baseline only ✅
  - enhance_features.py temporal features: within-run only (same label) ✅
  - Pipeline internals (Imputer, Scaler, Spline): fit on train only ✅
  - Run-level voting: post-prediction aggregation on test only ✅

Minor note: Temporal slope uses all windows in a run (including future).
Not cross-subject leakage since same run = same label. Acceptable for
retrospective analysis.
